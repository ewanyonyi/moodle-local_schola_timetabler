## 🔒 1. Overview & Commitment to Privacy

The **Schola Timetabler** Moodle plugin (`local_schola_timetabler`) is designed to manage institutional timetabling, course period assignments, room capacities, and examination schedules. We are committed to protecting the privacy of educational institutions, administrators, educators, and students.

This Privacy Policy explains how data is collected, stored, processed, and transmitted by the Schola Timetabler plugin.

---

## 💾 2. Local Data Storage (On-Premise Moodle Database)

All operational data generated by the plugin is stored strictly inside your local Moodle site database in dedicated custom tables:

- **`local_schola_timetabler_rooms`**: Stores campus venue names, seating capacities, and laboratory capability flags.
- **`local_schola_timetabler_slots`**: Stores time period definitions (days of week, start times, end times, and schedule types).
- **`local_schola_timetabler_breaks`**: Stores tea break and lunch window blockouts.
- **`local_schola_timetabler_schedules`**: Stores generated weekly schedule assignments (mapping course IDs, room IDs, slot IDs, teacher IDs, timetable titles, and timestamps).

### Personally Identifiable Information (PII)
- **Students**: The plugin does **NOT** collect, store, or process student names, email addresses, grades, or personal student records.
- **Teachers / Instructors**: The plugin references teacher account IDs (`teacherid`) from the core Moodle user table solely to prevent instructor double-booking conflicts during timetable generation.

---

## ⚡ 3. Pro Cloud Solver Acceleration Engine Data Transmission

The plugin supports dual constraint satisfaction engines:

### A. Native PHP Engine (Default / Free Edition)
- Runs 100% locally on your Moodle server under GPLv3.
- **Zero data leaves your Moodle server.**

### B. Pro Rust Cloud Engine (Commercial Option)
When the Pro Cloud Acceleration Engine is activated via a commercial license key:
- Timetable generation requests (`POST /api/v1/solve`) are sent to the high-performance Rust Cloud Solver service over encrypted HTTPS (`TLS 1.3`).
- **Transmitted Data Payload**: The payload consists exclusively of anonymized numerical matrix pairs:
  - `course_id` (integer)
  - `room_id` (integer)
  - `slot_id` (integer)
  - `teacher_id` (integer)
  - `title` (text identifier)
- **No PII Transmission**: User names, passwords, email addresses, student identities, or user profiles are **NEVER** transmitted to the cloud solver engine.
- **Stateless & Transient Processing**: Cloud solver requests are processed strictly in-memory ($O(1)$ collision lookup). No course matrices or timetable solutions are persistently stored on cloud solver servers after the HTTP response is completed.

## 🛡️ 4. Compliance with Moodle Privacy API

The `local_schola_timetabler` plugin implements Moodle's core Privacy API (`\core_privacy\local\metadata\null_provider`). Because the plugin does not store user personal data requiring GDPR export or erasure actions beyond standard Moodle core user reference IDs, it satisfies all Moodle Marketplace privacy compliance checks.
